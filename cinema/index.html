    Google カレンダーに追加

    Google カレンダーのボタンは予定作成画面を開くだけで、この端末の外へデータを送りません。.ics は Apple カレンダー等でも読み込めます。

    決済（Phase 2 予定）

    いまは座席の確保までで止めています。確保後は保持時間（モックでは10分）のうちに、 劇場サイトの決済画面で自分で購入を完了させる運用です。

    • Phase 2 ローカル runner（Node + Playwright）から決済フォームを自動入力
    • Phase 2 カード情報は OS キーチェーンに保存し、ブラウザ側には一切置かない
    • Phase 2 購入完了メールの検知 → カレンダー登録までを自動化

    いま、どのデータがどこにあるか

    データ保存先外部送信
    予約プラン（劇場・作品・上映回・座席候補）この端末の localStorageなし
    実行ログメモリのみ（リロードで消える）なし
    予約者情報（氏名・電話・メール）下の設定を ON にしたときのみ localStorageなし
    劇場サイトの会員ID・パスワードこのツールでは扱いませんなし
    クレジットカード情報このツールでは扱いませんなし

    このページは GitHub Pages 上の静的サイトで、サーバ側の保存領域を持ちません。 入力内容はブラウザから出ないため、外部に漏れる経路がそもそもありません。 ただし共用PCでは localStorage が他の利用者から読めるので、下のボタンで消してください。

    Phase 2 で認証情報が必要になったら

    実際にログインして座席を押さえる段階では、会員IDとパスワードが要ります。そのときの方針を先に決めておきます。

    • ブラウザには置かない。 認証情報は手元PCで動く runner だけが持ち、静的サイト側は一切受け取りません。
    • OS のキーチェーンに預ける。 macOS Keychain / Windows 資格情報マネージャー / libsecret に保存し、平文の設定ファイルには書きません。
    • リポジトリには絶対に入れない。 認証情報を含むファイルは .gitignore で除外し、コミット前に検知する仕組みを入れます。
    • ログに残さない。 runner のログは会員番号・カード番号をマスクしてから出力します。
    • 予約は自分の1件だけ。 複数アカウントの並列実行や転売目的の大量確保には対応しません。

    予約者情報（任意）

    Phase 2 で予約フォームの自動入力に使います。OFF のあいだは入力しても保存されません。

    自動化を使ううえでの前提

    • 劇場サイトの利用規約で自動アクセスが禁止されている場合があります。使う前に対象サイトの規約を確認してください。
    • このツールは自分が観る1件の予約を取ることだけを想定しています。転売目的の大量確保はできない作りにしてあります。
    • リクエスト間隔には下限（500ms）を強制しています。連打はサーバ負荷になるだけでなく、遮断されて成功率も下がります。
    • 確保に失敗しても、そのぶん誰かが観られています。取れなかったときに粘り続けない打ち切り時間を必ず設定してください。
