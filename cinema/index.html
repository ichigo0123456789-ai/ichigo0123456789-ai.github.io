発売の瞬間の速さ

「速く取る」の中身はほぼ次の3つです。順に効きます。

欲しい席が決まっているなら、座席表を取ってから確保するのは1往復ぶん遅いだけです。 発売の瞬間はいきなり確保を投げ、失敗して初めて座席表を取りにいきます。 発売から5秒以上経って始めた場合は、空振りのほうが高くつくので自動的に無効になります。

サーバ時刻と同期（自動）

手元の時計が2秒遅れていれば、どれだけ速いコードでも2秒出遅れます。 この実行画面を開くと自動で測定し、実行時にズレを自動補正します（3分ごとに測り直し）。 HTTP の Date ヘッダを繰り返し測り、秒境界をまたぐサンプルを交差させてサブ秒まで絞り込みます。

決済（Phase 2 予定）

いまは座席の確保までで止めています。確保後は保持時間（モックでは10分）のうちに、 KINEZO の決済画面で自分で購入を完了させる運用です。

  • Phase 2 カード情報は OS キーチェーンに保存し、ブラウザ側には一切置かない
  • Phase 2 購入完了メールの検知 → カレンダー登録までを自動化

認証情報の方針

実際の予約は手元PCの runner が行います。会員情報はチェーンごとに手元だけで管理し、このサイトには一切入れません。

  • 保管は手元の runner/.env だけ。 使う映画館の会員ID/パスワードを本人が記入します（.gitignore 済み＝コミットされません）。このサイトは認証情報を受け取りません。
  • チェーンごとに分離。 KINEZO・109・TOHO・チネチッタ・サンシャイン・映画ランドで変数を分け、混用しません。
  • クラウド送信なし。 認証情報はログ・チャット・コミットのどこにも出しません。
  • 予約は自分の1件だけ。 複数アカウントの並列実行や転売目的の大量確保はしません。行列スキップや連打もしません。
  • カード情報は保存しない。 券種選択・決済は各映画館の画面でご自身が行います（自動選択しません）。

座席データについて

全9スクリーンの座席配置・席番号は KINEZO の座席選択画面から採取した実データです （2026-08-20 取得）。席番号はスクリーンに向かって左からのグリッド位置で、 KINEZO の実際の座席ID（例 C-7）と一致します。縦通路はグリッドの欠番、 横通路は列の欠落として実物どおりに表れます。合計1,212席で公開情報とも一致します。

上映スケジュールの時間帯だけはサンプルのままです（作品名は実ラインナップ）。 実際の番組表・空席状況の取得は Phase 2 で対応します。 車椅子スペースは KINEZO のオンライン座席選択に表示されない（劇場問い合わせ）ため、座席表には含めていません。

自動化を使ううえでの前提

  • KINEZO の利用規約で自動アクセスが禁止されている場合があります。使う前に必ず規約を確認してください。
  • このツールは自分が観る1件の予約を取ることだけを想定しています。転売目的の大量確保はできない作りにしてあります。
  • リクエスト間隔には下限（500ms）を強制しています。連打はサーバ負荷になるだけでなく、遮断されて成功率も下がります。
  • 確保に失敗しても、そのぶん誰かが観られています。取れなかったときに粘り続けない打ち切り時間を必ず設定してください。
